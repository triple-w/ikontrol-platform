# iKontrol 1.1.5

Release date: 2026-10-08. Release reference: `release/1.1.5`.

This bugfix centralizes commercial stamp-wallet resolution by company, issuer RFC and fiscal environment. Invoice stamping, payment complements, credit notes, cancellation preflight/execution, the fiscal balance screen and administrative history now resolve the same physical wallet. Development and production remain isolated, ambiguous wallets fail closed, and no balance or movement is changed by the release upgrade itself.

The directed path is `1.1.4 -> 1.1.5`, release ID `ikontrol-1.1.5-canonical-stamp-wallet-resolution`, with the single `record_version` step. It does not run migrations or distribute application files.

Application code must already have been deployed from a verified 1.1.5 artifact before running:

```bash
php spark ikontrol:upgrade:plan --target=1.1.5 --json
php spark ikontrol:upgrade --target=1.1.5 --yes --json
```

The repository currently has no iKontrolAdmin-connected release artifact deployer. Do not use an unmanaged `git pull` on customer instances. A future deployment service must stage and verify a signed/checksummed artifact, preserve instance-owned paths, switch code atomically, run the directed upgrade, execute health checks and restore both code and database backup on failure.

Instance-owned paths that must never be replaced by the code artifact include `.env`, `writable/`, runtime uploads and files, private fiscal material, branding and other explicitly declared per-instance overrides.
