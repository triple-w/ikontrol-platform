# iKontrol 1.0.0

Fecha de release: 2026-10-01. Referencia: `v1.0.0`.

## Incluye

- Instalación canónica en una base MySQL vacía mediante `ikontrol:install-canonical`.
- Proposals con plantillas legacy/fiscales, preview/PDF coherente y conversión transaccional a venta.
- Historial formal y costos manuales de proveedor con idempotencia y comparación.
- Movimientos, transferencias, recepción parcial y etiquetas de almacén.
- Pagos administrativos y complementos internos, externos y mixtos sin crear documentos administrativos ficticios.
- CFDI de ingreso, pago y egreso con ambiente fiscal sandbox/production, sólo validado con fake/MOCK.
- Lifecycle de timbrado seguro: retry restringido, conciliación de estado incierto, locks y wallet.
- Series, folios, XML y PDF basados en evidencia fiscal persistida.
- Rutas explícitas, verbos HTTP, CSRF y permisos para los flujos reconciliados.

## Validación

La release aprobó smoke de instalación limpia (36), Baseline (13), Proposals (13), Suppliers (21), Warehouses (11), ambiente fiscal (16), lifecycle fiscal (26), complementos (28), series/PDF (32) y superficie HTTP (24). Todas las pruebas usaron fixtures o schemas temporales aislados; no hubo PAC real.

## Límites conocidos

La activación productiva requiere onboarding fiscal por instancia, CSD, credenciales y opt-in de producción. Las instancias existentes no se actualizan automáticamente: requieren el procedimiento dirigido de [UPGRADING_EXISTING_INSTANCES.md](../UPGRADING_EXISTING_INSTANCES.md). No ejecute `php spark migrate` global ni `db:build-clean` sobre datos existentes.
